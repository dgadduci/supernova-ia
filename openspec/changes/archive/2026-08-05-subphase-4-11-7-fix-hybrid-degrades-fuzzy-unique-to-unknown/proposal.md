## Why

Subphase 4.11.5 closed the residual fuzzy failures and the false-positive ambiguity leak on the restricted-pending scope, and Subphase 4.11.6 closed the remaining `C401` Ruff findings. The 47-case calibration is otherwise green: 41/47 cases are `correct`, `false_positives.count == 0`, and `false_unknowns.count == 6`.

The remaining 4 `real_hybrid_recognizer_failure` cases share a single failure mode that the Subphase 4.11.5 guard does NOT cover:

| `case_id`                       | `input_text`                       | `catalog_scope`                       | `actual_fuzzy_decision` | `actual_hybrid_decision` |
| ------------------------------- | ---------------------------------- | ------------------------------------- | ----------------------- | ------------------------ |
| `product-plus-presentation`     | `una pizza muzza grande`           | `in_memory` (`pizza_mozzarella_presentations`) | `unique(pid=2)`         | `unknown`                |
| `fuzzy-misspelling-mozzarella`  | `piza mozarela`                    | `in_memory` (`pizza_mozzarella_short`) | `unique(pid=100)`       | `unknown`                |
| `supported-mozza-alias`         | `pizza muzza`                      | `in_memory` (`pizza_mozzarella_short`) | `unique(pid=100)`       | `unknown`                |
| `multi-word-jamon-queso-dynamic`| `empanada de jamon y queso`        | `commerce_dynamic_database`           | `unique(pid=33)`        | `unknown`                |

Every one of these cases has a single fuzzy candidate (`len(observation.fuzzy_ids) == 1`) and an empty vector contribution (`len(observation.vector_ids) == 0`). The combined hybrid `ranking` therefore reduces to `observation.fuzzy_ids`, and the combined hybrid `scores` reduce to `policy.fuzzy_weight * fuzzy_score + policy.vector_weight * 0 = policy.fuzzy_weight * fuzzy_score`. Because the input does not equal the canonical `producto_nombre` (it has article + size / spelling / multi-word form), `_exact_flags` returns `canonical=False, alias=False`, so the `ranking and (canonical or alias)` short-circuit at the top of `_decision` does NOT fire. The decision then falls through to the `top_score >= policy.unique_threshold` check, where `policy.fuzzy_weight * fuzzy_score` (e.g. `0.5 * fuzzy_score` or `0.6 * fuzzy_score`) does not always meet `policy.unique_threshold` (e.g. `0.65`–`0.75`), so the hybrid returns `unknown` even though the fuzzy produced the correct unique decision.

This is the symmetric counterpart to the Subphase 4.11.5 guard: 4.11.5 protected `fuzzy_ambiguous + restricted_scope` from being promoted to `unique` by the vector; 4.11.7 must protect `fuzzy_unique + empty_vector` from being degraded to `unknown` by the score-threshold gating. Without this guard, the four cases stay `real_hybrid_recognizer_failure` even though they are correct at the recognizer level — the calibration is artificially gated at 41/47.

## What Changes

Add a single, additive guard inside `_hybrid_prediction` in `backend/services/product_recognition_calibration_runner.py`. The guard is the positional counterpart of the Subphase 4.11.5 guard:

- **If** `observation.fuzzy_decision == "unique"` **and** `observation.vector_ids` is empty (no vector contribution), the runner returns the fuzzy prediction verbatim (`fuzzy_decision="unique"`, `top_id=observation.fuzzy_ids[0]`, `ranking=observation.fuzzy_ids`, `scores=observation.fuzzy_scores`, with `_exact_flags` applied to the fuzzy ranking).
- **Otherwise**, the existing scoring rule is preserved verbatim. The guard never fires for `fuzzy_decision == "ambiguous"` (which is the precondition the Subphase 4.11.5 guard requires, so the two guards are mutually exclusive on `fuzzy_decision` and the new guard never short-circuits the 4.11.5 guard), for `fuzzy_decision == "unknown"`, for any non-empty `vector_ids`, or for any other path through `_hybrid_prediction`. The new guard is scope-independent: it does NOT inspect `catalog_scope` and therefore can fire for `pending_product_selection_restricted` cases whenever the precondition holds (which is impossible in the current dataset, but the guard itself imposes no scope restriction).

The fix is concentrated in `_hybrid_prediction` and in the `StrategyPrediction` it returns; no other file is touched, no policy is altered, no policy grid is modified, and the `eligibility` verifier is unchanged. The Subphase 4.11.5 guard continues to fire for the `pending_product_selection_restricted` + `fuzzy_ambiguous` case (`ambiguous-empanada-carne`); the Subphase 4.11.7 guard handles the orthogonal `fuzzy_unique + empty_vector` case.

A focused regression test suite is added at `backend/tests/test_product_recognition_calibration_4_11_7.py` to pin the behaviour. After the fix, the full 47-case calibration is re-run with `calibration_after.json` and `calibration_after_diagnose.json` regenerated under `openspec/changes/subphase-4-11-7-fix-hybrid-degrades-fuzzy-unique-to-unknown/diagnostics/`. The pre-rewrite 47-case baseline is preserved under `openspec/changes/subphase-4-11-7-fix-hybrid-degrades-fuzzy-unique-to-unknown/diagnostics/before.json` and `before.diagnose.json`.
