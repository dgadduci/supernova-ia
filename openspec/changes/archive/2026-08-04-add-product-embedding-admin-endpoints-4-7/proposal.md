## Why

Subphase 4.6 shipped per-document embedding indexing through a CLI-only surface (`backend/scripts/seed_product_presentation_embeddings.py`). The indexer, status state machine, hash-based idempotency, commerce isolation, dry-run classification, and recovery semantics all work — but the only way to exercise them today is from the operator's shell. Local development needs HTTP triggers for reindex and status so the catalog can be regenerated, audited, and inspected without shelling into the container, and so the embedding pipeline can be wired to the rest of the Phase 4 hybrid recognizer stack incrementally as later subphases ship.

## What Changes

- Introduce a local administrative FastAPI router gated behind a new `ENABLE_LOCAL_ADMIN_ENDPOINTS` setting (default `false`, override via env var). The router returns `404` for every route when the flag is disabled so the surface is indistinguishable from a non-existent route during normal operation.
- Add `POST /admin/comercios/{comercio_id}/product-embeddings/reindex` that accepts an optional JSON body (`producto_id`, `producto_presentacion_id`, `force`, `dry_run`, `batch_size`), validates the `comercio_id`, and delegates the work to the existing Subphase 4.6 `ProductoPresentacionEmbeddingIndexer` / `ProductoPresentacionEmbeddingSeeder` services through the seeder's public surface. The route handler relies on `backend.dependencies.get_session` injected through `Depends(get_session)` for the FastAPI session lifetime, owns the inner transaction boundary (`session.commit()` once after a completed real reindex, no commit on `dry_run`, `session.rollback()` once on an unhandled exception), and never calls `session.close()` — the existing `get_session` generator remains the sole owner of `session.close()` in its `finally`.
- Add `GET /admin/comercios/{comercio_id}/product-embeddings/status` that returns a commerce-scoped summary of `producto_presentacion_embeddings` rows: commerce id, configured `embedding_model`, configured dimension, total rows, counts by `embedding_status` (`pending` / `ready` / `failed` / `stale` / `inactive`), active row count, count of rows with non-null `last_error`, and counts by `source_type` when they fit the existing repository shape.
- Reuse the existing 4.6 indexer, seeder, repositories, persistence model, settings, status values, and `EmbeddingStatus` enum. Do not duplicate batching, hash comparison, stale / inactive handling, failure handling, or dry-run logic.
- Expose only the minimum HTTP surface required for local development. No users, roles, JWT, OAuth, API keys, sessions, background jobs, Celery, Redis, or automatic catalog-change regeneration. Disabled local-admin endpoints return `404` (not `403`) so the surface is invisible by default.
- A completed run with recoverable embedding failures may return a successful HTTP response containing `failed > 0`; every Ollama failure is represented in the result counters instead of being re-raised as an unhandled server exception. The status response never returns full embedding vectors, customer messages, credentials, internal exception traces, or any unsafe internal details. SQLAlchemy queries live only in repositories.

## Capabilities

### New Capabilities

- `product-embedding-admin-endpoints`: local administrative FastAPI endpoints (`POST /admin/comercios/{comercio_id}/product-embeddings/reindex`, `GET /admin/comercios/{comercio_id}/product-embeddings/status`) gated behind `ENABLE_LOCAL_ADMIN_ENDPOINTS`, delegating to the existing Subphase 4.6 indexer / seeder / repository surface; the route handlers use `Depends(get_session)` to receive the session and own only the inner transaction boundary (`commit` once after a completed real reindex, no commit on `dry_run`, `rollback` once on an unhandled exception); response payloads exclude vectors and unsafe internal details.

### Modified Capabilities

- `product-presentation-embedding-indexing`: extend the existing capability with the local-admin endpoint requirements (gate, request validation, response shape, transaction ownership, error mapping, vector-exclusion rule, commerce isolation). No requirement changes to the indexer, seeder, repositories, or persistence model — the indexer's surface and CLI contract remain unchanged.
- `producto-presentacion-embeddings`: extend the existing capability with the new `ENABLE_LOCAL_ADMIN_ENDPOINTS` setting (boolean, default `false`, env var, positive validator optional) and document that the new repository read used by the status endpoint is a per-status / per-source-type aggregation over the existing per-document table.

## Impact

- New modules:
  - `backend/routers/admin_product_embeddings.py` — FastAPI `APIRouter` exposing the two endpoints, receives the SQLAlchemy session through `Depends(get_session)` (the existing `backend.dependencies.get_session` generator, which already owns `session.close()` in its `finally`), owns only the inner transaction boundary (`session.commit()` once after a completed real reindex, no commit on `dry_run`, `session.rollback()` once on an unhandled exception), and never calls `session.close()`. `404` short-circuit when `ENABLE_LOCAL_ADMIN_ENDPOINTS` is `false`. Response mapping only — no SQLAlchemy queries, no hashing, no batching.
  - `backend/services/producto_presentacion_embedding_admin_service.py` — small admin-facing service that owns the `OllamaEmbeddingClient` (whose constructor remains `(settings, transport=None, clock=None)`), the `ProductoPresentacionEmbeddingIndexer`, and the `ProductoPresentacionEmbeddingSeeder` (preferred through constructor / factory injection so tests can substitute fakes without instantiating a real Ollama transport); wraps them for reindex and uses the existing 4.3 / 4.6 status repository for status; performs `comercio_id` existence validation, scope-filter validation, and `batch_size` validation. Lifts `SeedingResult` and the status row aggregates into stable response DTOs. Never calls `commit` / `rollback` / `close` / `begin`. Never contains raw SQLAlchemy queries. Never imports FastAPI.
  - `backend/repositories/producto_presentacion_embedding_status_repository.py` — small repository that aggregates `producto_presentacion_embeddings` per commerce: counts by `embedding_status`, counts by `source_type`, active count, count of rows with non-null `last_error`, total rows, joined-loaded presentation chain for diagnostics that already exist in the model. SQLAlchemy queries only.
  - `backend/schemas/product_embedding_admin.py` — Pydantic request / response DTOs (`ProductEmbeddingReindexRequest`, `ProductEmbeddingReindexResponse`, `ProductEmbeddingStatusResponse`, `ProductEmbeddingStatusCounts`, error mappers to HTTP).
- Modified modules:
  - `backend/config/settings.py` — add `enable_local_admin_endpoints: bool = False` to the frozen `Settings` dataclass (env var `ENABLE_LOCAL_ADMIN_ENDPOINTS`, default `False`, validated via `_bool_env`).
  - `backend/main.py` — register the new admin router alongside the existing routers.
  - `backend/services/exceptions.py` — add `LocalAdminEndpointsDisabled`, `InvalidProductEmbeddingAdminScope`, `InvalidBatchSize` exceptions; HTTP mappings decided at the router layer.
- New tests (minimum indispensable surface, fastapi `TestClient` against fake indexing dependencies, no real Ollama):
  - `backend/tests/test_admin_product_embeddings_endpoints.py` — covers the nine focused cases from `openspec/specs/project.md` §4.7: endpoints unavailable when disabled (`404`); status endpoint commerce-isolation + correct status counters; status response never exposes vectors; reindex passes the commerce scope and accepted options to the 4.6 service; dry-run performs no commit; completed real run commits once; unhandled failure rolls back; missing commerce / invalid scope return intended HTTP errors; recoverable embedding failures return counters with `failed > 0` without leaking internal details.
  - `backend/tests/test_admin_product_embeddings_module_boundaries.py` — `grep`-based boundary assertions on the new router / service / repository: the router never imports `sqlalchemy`, never calls `db.close()` (only `db.commit()` and `db.rollback()`), never imports `backend.llm` / `backend.repositories` / `backend.scripts`; the admin service never imports `fastapi` / `sqlalchemy`, never calls `commit` / `rollback` / `close` / `begin`, and instantiates `OllamaEmbeddingClient(settings)` only through its existing `(settings, transport=None, clock=None)` constructor (the constructor is unchanged); the status repository never imports HTTP, FastAPI, the embedding client, the indexer, the seeder, the admin service, or any router.
- No change to the embedding client constructor, the pure `ProductEmbeddingDocumentBuilder`, the `OllamaEmbeddingClient`, the indexer, the seeder, the persistence model, the migration, the existing CLI, the existing FastAPI routers, or any Subphase 4.1 — 4.6 behavior. The remaining Phase 4 subphases (Subphase 4.8 similarity search + HNSW / IVFFlat, Subphase 4.9 hybrid recognizer wiring, automatic catalog-change hooks, real authentication) stay explicit non-goals.
- Use the exact change identifier `add-product-embedding-admin-endpoints-4-7` everywhere — in paths, scripts, and `openspec validate`.
- The OpenSpec change remains active after `/opsx:apply`; specification synchronization (`/opsx:sync`) and archival (`/opsx:archive`) are explicit user commands per the project's workflow rule.
