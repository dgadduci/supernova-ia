# Social conversation responses

## ADDED Requirements

### Requirement: Deterministic social turns

When the existing authoritative classifier emits `saludo`, `agradecimiento`, `despedida`, `respuesta_afirmativa`, `respuesta_negativa`, or `desconocida` while the session has no pending context, the system SHALL return exactly one deterministic, brief Spanish customer response through the existing response-mapper and outbound path. The turn SHALL not mutate session, pedido, order lines, payment, delivery, or pending state.

#### Scenario: Greeting is handled through the common response path

- **WHEN** the classifier emits `saludo` for an initial message and the session has no context
- **THEN** the dispatcher returns a successful non-mutating processed intent
- **AND** the mapper produces the fixed greeting response
- **AND** the provider outbox and local response surfaces receive that same response in the existing ordering.

#### Scenario: Unknown message gets a recovery response

- **WHEN** the classifier emits `desconocida` for an initial message and the session has no context
- **THEN** the system returns the fixed reformulation guidance
- **AND** it does not treat a technical failure as an unknown-message outcome.

### Requirement: Pending contexts retain precedence

The system SHALL keep pending-context dispatch ahead of social-turn handling. An affirmative or negative classifier result SHALL NOT bypass an active pending context.

#### Scenario: Affirmation during product selection

- **WHEN** a session has an active product-selection context and the customer replies affirmatively
- **THEN** the existing pending-context dispatcher handles the message
- **AND** no social response is generated by the initial dispatcher.

### Requirement: Unsupported intent fallback remains unchanged

For classifier intents outside the approved social set and existing implemented mappings, the system SHALL retain the existing generic fallback behavior until their own OpenSpec change is approved.

#### Scenario: Deferred informational intent

- **WHEN** the classifier emits `ver_menu`
- **THEN** the system does not fabricate menu content or introduce a new response path
- **AND** it preserves the existing generic fallback response.
