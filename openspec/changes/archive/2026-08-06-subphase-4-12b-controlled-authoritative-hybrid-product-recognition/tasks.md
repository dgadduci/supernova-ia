## 4. Hybrid Authoritative Recognizer

- [x] 4.1 Create `backend/services/hybrid_authoritative_recognizer.py` with `HybridAuthoritativeProductRecognizer` that implements `ProductRecognizerProtocol` and exposes `recognize(text, catalog, *, intent_metadata=None) -> ProductRecognizerResult`. The recognizer SHALL NOT import anything intent-specific.
- [x] 4.2 Implement the fuzzy-first pipeline: invoke the injected `FuzzyProductRecognizer` exactly once, measure its latency, use the result as the authoritative fuzzy side.
- [x] 4.3 Implement the commerce-id resolver short-circuit: when the resolver returns `None`, return the fuzzy result byte-for-byte and skip the recorder.
- [x] 4.4 Implement the embedding + vector pipeline: call `_normalizar_texto(text)`, the injected `OllamaEmbeddingClient.embed_query`, and the injected `ProductPresentationVectorSearchService.search_similar` with `top_k=policy.vector_top_k`, `candidate_producto_presentacion_ids=None`. Translate any exception to a sanitized failure category and fall back to the fuzzy result byte-for-byte. The raw `vector_ids` and `vector_scores` returned by the search service SHALL be passed to the catalog-scope filter step (4.6) before any guard, scoring, ranking, or translation is performed; the recognizer SHALL NOT consult any guard, score, ranking, or translator that consumes unfiltered vector results.
- [x] 4.5 Build `allowed_candidate_ids` exclusively from the `catalog` argument received by `recognize(...)`. The set SHALL contain every `producto_presentacion_id` present in the catalog rows (deduplicated). The catalog passed to `recognize(...)` is the complete authoritative candidate universe for the current recognition call; the recognizer SHALL NOT query or reload the full commerce catalog to expand this set and SHALL NOT reintroduce candidates discarded by the 4.12A narrowing flow. `allowed_candidate_ids` SHALL be built once per call and SHALL be reused by every filter (4.6), guard (4.7, 4.8), scoring step (4.9), ranking step (4.9), and translation step (4.10) that follows. The recognizer SHALL apply this rule for every catalog passed to `recognize(...)`, not only when `intent_metadata["catalog_scope"] == "pending_product_selection_restricted"`.
- [x] 4.6 Filter the raw `vector_ids` and `vector_scores` returned by the search service (4.4) against `allowed_candidate_ids` (4.5) BEFORE applying the 4.11.5 guard (4.7), the 4.11.7 guard (4.8), hybrid scoring (4.9), ranking (4.9), and decision translation (4.10). Discard any raw vector result whose `producto_presentacion_id` is not present in `allowed_candidate_ids`. The filtered `vector_ids` and `vector_scores` SHALL be the only vector side consumed by every subsequent step. If no raw vector candidate survives the filter, the vector side SHALL be treated as empty (`vector_ids == []`, `vector_scores == []`); the 4.11.7 guard SHALL evaluate the filtered empty vector side and SHALL activate as documented when `fuzzy_decision == "unique"`. Filtering every raw vector result out SHALL NOT trigger a technical fallback to fuzzy; the recognizer SHALL continue with the filtered empty vector side and the existing fuzzy pipeline (this is a valid semantic outcome, not an infrastructure failure). Commerce isolation is enforced by this filter: a vector result from another commerce cannot appear in the final result because `allowed_candidate_ids` is derived from the commerce-specific catalog passed to `recognize(...)`. Duplicate vector IDs in the retained results SHALL be deduplicated AFTER the filter step, not before.
- [x] 4.7 Port the 4.11.5 guard verbatim (`catalog_scope == "pending_product_selection_restricted"` AND `fuzzy_decision == "ambiguous"` → force `ambiguous`). Read `catalog_scope` exclusively from `intent_metadata.get("catalog_scope")` when supplied; when `intent_metadata` is `None` or its `catalog_scope` is not the documented restricted literal, the guard SHALL be short-circuited and SHALL NOT fire. The 4.11.5 guard SHALL consume the filtered `vector_ids` from 4.6 (not the raw search results).
- [x] 4.8 Port the 4.11.7 guard verbatim (`fuzzy_decision == "unique"` AND `len(filtered_vector_ids) == 0` → force `unique`). The 4.11.7 guard SHALL consume the filtered `vector_ids` from 4.6; the raw search results SHALL NOT be consulted by the guard. The guard SHALL fire when the fuzzy decision is `"unique"` and the FILTERED vector side is empty, regardless of whether the raw search returned any results that were discarded by the catalog-scope filter.
- [x] 4.9 Implement the hybrid scoring using the calibrated `HybridDecisionPolicy`: `policy.fuzzy_weight * fuzzy_score + policy.vector_weight * vector_score`, top fuzzy score `1.0`, subsequent fuzzy scores non-increasing in encounter order, vector scores clipped to `policy.vector_top_k` AND drawn exclusively from the filtered `vector_ids`/`vector_scores` from 4.6. The hybrid ranking SHALL be built from the filtered candidates only; no candidate outside `allowed_candidate_ids` SHALL appear in the ranking. Ambiguous and unknown hybrid outcomes (after the 4.11.5 / 4.11.7 guards) SHALL remain authoritative when the filtered vector side is empty — the recognizer SHALL NOT fall back to fuzzy merely because the filter discarded every raw vector result.
- [x] 4.10 Implement `_translate_hybrid_decision(decision, ranking, normalized_text) -> ProductRecognizerResult` mapping `"unique"` → single-entry `encontrados`, `"ambiguous"` → single `encontrados_posibles` group, `"unknown"` → single-entry `no_encontrados`. The `ranking` consumed by the translator SHALL be the filtered ranking from 4.9 only; no raw, unfiltered, or out-of-scope candidate SHALL appear in the translated result. Preserve the `ProductRecognizerResult` invariants (no `None` lists, descending score order, dedupe on duplicate `producto_presentacion_id`).
- [x] 4.11 Wire the recorder call: `recorder.record(..., mode="hybrid_authoritative")` with the existing comparison + observation payload. The observation payload SHALL record the filtered `vector_ids` and `vector_scores` from 4.6, not the raw search results, so the recorded telemetry reflects what the runtime guards, scoring, ranking, and translation actually consumed.
- [x] 4.12 Export `HybridAuthoritativeProductRecognizer` through `__all__`.
